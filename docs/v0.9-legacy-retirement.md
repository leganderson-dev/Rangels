# Rangels V0.9 — Legacy Retirement

V0.9 completes the transition from Alzex category paths to Rangels' active classification model.

## Active model

Every new non-transfer transaction is classified with:

- Purpose
- Context
- Household Bucket when the Context and Purpose make it applicable
- Tax treatment
- Reimbursement status and optional tags

Transfers use Transfer Reason and, only when relevant, a Funding Context. They do not create income or spending merely because money moved between owned accounts.

## Dormant audit references

`transactions.category_id` and `transactions.legacy_category_id` remain nullable database fields. Existing values are preserved exactly for audit and rollback. New transactions leave both fields null, and neither field drives the UI, imports, merchant rules, reporting, budgets, or schedules.

The readable former path also remains in each migrated transaction note as `Legacy classification: …`.

## Feature reset

The pre-V0.9 Budget, Plan, Report, and Scheduled surfaces were prototypes. Budget and scheduled configuration rows were snapshotted and then reset so these features can be rebuilt against Purpose and the rest of the canonical model without compatibility compromises. Reports and Plan derive from the canonical transaction dimensions.

## Recovery

The migration creates the database schema `backup_20260809_v09_legacy_retirement`. The paired rollback SQL restores the reset configuration tables and legacy classification trigger. Application rollback is also available through the V0.9 Git tag and its preceding commit.
